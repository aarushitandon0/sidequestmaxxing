## Why `kept` is 0

Two findings, both upstream of our code.

**1. The `google_events` engine is gone.** The first run of this script returned
`400 Unsupported ``google_events`` search engine.` on all four queries. SerpApi's changelog for
2026-08-24 states: *"The Google Events API has been deprecated and no longer accepts new
requests. Event data is still available via the `events_results` field of the Google Search
API."* The script now sends `engine=google` and reads the same `events_results` array. That
part works — hence `fetched 10`.

**2. The replacement payload is a different, thinner schema** than the one the P23 spec
(section 4) and `app/services/serp_events.py` were written against. Every one of the 10 entries
has exactly these keys:

```json
{
  "title": "Shubham Karoti",
  "type": "Contemporary Marathi drama",
  "date": "11 Oct",
  "time": "5:00",
  "address": ["Balagandharv Rang Mandir", "Shivajinagar"],
  "thumbnail": "https://encrypted-tbn0.gstatic.com/..."
}
```

Against the spec's assumed shape, this is missing:

| Spec assumes | `engine=google` events pack | Consequence |
|---|---|---|
| `date.when` (`"Sat, Oct 11, 7:00 AM"`) | `date` = `"11 Oct"`, `time` = `"5:00"` | `parse_event_window` finds no meridiem and refuses to guess → all 10 land in `no_time` |
| `date.start_date` | absent | same |
| `venue.name` | venue is `address[0]` | tier-1 place match has no venue field to read |
| `link` (the listing URL) | **absent** | spec section 7.1 and the Task 9 "see the listing" link have no URL to show |
| `ticket_info` | absent | the ticketed filter degrades to the price regex alone |

`time: "5:00"` is the blocking ambiguity: a 5:00 Marathi drama is almost certainly 17:00, but
"almost certainly" is exactly the plausible-but-wrong datetime the Task 3 brief forbids. A wrong
guess sends a player to a venue twelve hours off.

**3. The events that do come back are the wrong kind of event.** All 10 are indoor, paid
theatre and concert listings (Balagandharv Rang Mandir, antiSOCIAL, The Box Hub). The spec's
premise is outdoor, free, daylight, public-place happenings — heritage and nature walks. Those
three queries returned nothing. Even with the schema fixed, invariant 1 (public places, daylight,
non-ticketed) would drop most of this set on purpose.

## Status

This is the spec section 13 risk landing, measured rather than assumed. The decision about how
to respond belongs to the project owner, not to this script. See `docs/DECISIONS.md` (OQ-E1),
which also records two findings from the branch review: the live pack prints dates day-first
(`"11 Oct"`), which the date regex does not read, and it carries no `description`/`ticket_info`,
so `banned 0` and `ticketed 0` above say nothing about how those filters behave on live data.
